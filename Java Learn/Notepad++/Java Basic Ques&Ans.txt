
1]What is Java?
 - Java is a high-level, object-oriented, platform-independent programming language developed by Sun Microsystems in 1995, now owned by Oracle. 
 - It follows the 'Write Once, Run Anywhere' (WORA) principle — code compiled into bytecode can run on any device with a JVM, regardless of the underlying OS or hardware.
 
2]Java Features
Java is known for the following key features:

Platform Independent – bytecode runs on any JVM ("compile once, run anywhere")
Object-Oriented      – everything modeled as objects (encapsulation, inheritance, polymorphism, abstraction)
Simple & Robust 	 – no explicit pointers, automatic garbage collection, strong type checking at compile time
Secure               – no explicit memory access, bytecode verification, sandboxing (classloader, security manager)
Multithreaded        – built-in support for concurrent programming (Thread class, Executor framework)
Java supports multiple threads to run simultaneously which improves performance for complex applications.
Architecture-neutral – no dependency on OS-specific data sizes
The bytecode generated by the compliter can runs on any device with JVM, regardless of the underlying OS or hardware.
High Performance     – JIT (Just-In-Time) compiler converts bytecode to native machine code at runtime
Distributed			 – supports RMI, networking APIs for distributed computing
Dynamic				 – supports dynamic loading of classes at runtime
Dynamic Loading of classes at runtime means:
 - When your program starts, the JVM only loads the classes required to begin execution (e.g., the class with main()).
 - Other classes are loaded lazily — the first time they're actually used (a new object is created, a static method is called, etc.).
 - This is handled by the ClassLoader subsystem of the JVM.

Functional Programming Support (Java 8+) – Lambda expressions let you write behavior as compact, inline functions instead of verbose anonymous classes, 
e.g. list.forEach(item -> System.out.println(item))
Streams API (Java 8+) 					 – enables declarative, pipeline-style processing of collections (filter, map, reduce, collect) 
instead of manual loops, making data transformations more readable and often more efficient
Module System / Project Jigsaw (Java 9+) – introduced the module-info.java construct, allowing applications to be broken into well-defined modules 
with explicit dependencies, improving encapsulation and reducing classpath issues

Why is Java more secure than C/C++?
 - Java is considered more secure because it provides a managed runtime environment and eliminates or restricts several unsafe low-level features. 
 - Java does not allow direct pointer manipulation or pointer arithmetic, provides automatic garbage collection, performs array bounds checking 
and bytecode verification, and uses strong type checking. 
 - These features reduce common vulnerabilities such as memory corruption, buffer overflows, dangling pointers, and use-after-free errors.

4]JDK, JRE, JVM Architecture:

JDK (Java Development Kit)
 - JRE + development tools (javac compiler, debugger, javadoc, jar, etc.)
 - Used to develop and run Java applications
JRE (Java Runtime Environment)
 - JVM + core libraries (java.lang, java.util, etc.) + supporting files
 - Used to run Java applications, not develop them 
JVM (Java Virtual Machine)
 - Abstract machine that provides runtime environment to execute bytecode
 - Platform-dependent (different JVM implementations for Windows/Linux/Mac), but the bytecode it runs is platform-independent
 -Components:
	* Class Loader Subsystem – loads, links, and initializes classes (Bootstrap, Extension, Application classloaders)
	* Runtime Data Areas 	 – Method Area, Heap, Stack, PC Registers, Native Method Stack
	* Execution Engine 		 – Interpreter, JIT Compiler, Garbage Collector
1. Interpreter
 - Reads the compiled .class bytecode line-by-line (instruction-by-instruction) and executes it directly, converting each bytecode instruction to native machine code on the fly.
 - Drawback: If the same method is called 1,000 times in a loop, the interpreter re-interprets and re-translates it every single time — this is slow for repetitive code.
2.JIT Compiler (Just-In-Time Compiler)
 - Solves the interpreter's performance problem by identifying "hot code" — methods or loops executed frequently — and compiling them directly into native machine code, 
which is then cached and reused instead of being re-interpreted each time.
3.Garbage Collector (GC)
 - Automatically manages memory by reclaiming heap memory occupied by objects that are no longer reachable/referenced by the application 
 - so you don't have to manually free memory like in C/C++.

5]How Java Code Works (Execution Flow)
 - Source code → compiled to bytecode by javac(Compiler) which is a .class file
 - JVM's ClassLoader loads the .class file into memory
 - Bytecode Verifier checks it for security violations (no illegal memory access etc.)
 → [loaded by classloader → verified]
 → executed by JVM's interpreter/JIT → memory managed by GC. 
 - This is what makes Java both platform-independent and reasonably performant.
 
6]Why is Java Platform Independent?
 - Java achieves platform independence because the compiler produces bytecode, not native machine code. That bytecode is the same on every platform 
 — it's the JVM, which is platform-specific, that handles translating it correctly for the underlying OS. This is the essence of 'Write Once, Run Anywhere.
 
7]What is javac?
 - javac is the Java compiler, part of the JDK. It takes your human-readable Java source code (.java files) and compiles it into bytecode (.class files) 
that the JVM can understand and execute.

8]What is Bytecode?
 - Bytecode is the compiled form of Java source code — a set of JVM instructions stored in .class files, 
which is platform-independent and gets interpreted or JIT-compiled by the JVM at runtime.

9]What is the main Method and What's Its Use?
 - The main method is the entry point of any standalone Java application.
 - It tells the JVM "start running the program from here."
 - String[] args allows command-line arguments to be passed into the program at runtime.
 
10]Why is main Method static and public?
 - Why static:- The JVM needs to call main() without creating an object of the class first
 - The JVM (which is external to your class/package) needs to access and invoke this method from outside the class
 - If it were private or default (package-private), the JVM wouldn't have the visibility/access rights to call it from outside
 - void: main doesn't return anything to the JVM — the program's exit status is instead communicated via System.exit(int status) if needed, not a return value

11]Is Java completely object-oriented?
 - Java is object-oriented, but it is not a pure object-oriented language because it supports primitive data types such as int, char, boolean and double, which are not objects.
 - Because in a purely object-oriented language, everything would be treated as an object. Java has primitives for performance and simplicity.

12]= vs ==
	= → assignment operator, assigns a value to a variable
	== → comparison operator, compares values (primitives) or references (objects)

13]break vs continue
	break — exits the loop (or switch) entirely
	continue — skips the current iteration and moves to the next one

14]Why doesn't Java support pointers?
 - Java doesn't expose explicit pointers or pointer arithmetic because it was designed to provide memory safety, security and simplicity. 
 - Java uses references for accessing objects and relies on the JVM and garbage collector for memory management. 
 - This prevents developers from directly manipulating arbitrary memory addresses.
 
15]Why doesn't Java support multiple inheritance through classes? 
 - Java doesn't support multiple inheritance through classes primarily to avoid ambiguity and complexity in inheritance, especially the diamond problem. 
 - Multiple class inheritance can create conflicts in method implementations, fields and constructor initialization. 
 - Instead, Java supports implementing multiple interfaces, which provides multiple types/contracts while allowing the implementing class to define the behavior.
 
16]if-else vs switch
 - if-else is preferred when we need to evaluate conditions, ranges, or complex boolean expressions. 
 - switch-case is preferred when we need to compare a single expression against multiple fixed values.


| `if-else`                               | `switch-case`                         |
| --------------------------------------- | ------------------------------------- |
| Used for conditions                     | Used for fixed values                 |
| Supports complex conditions             | Best for exact value matching         |
| Supports ranges                         | Not normally used for ranges          |
| Can use `>`, `<`, `>=`, `<=`, `&&`, `   |                                       |
| Good for `age >= 18`                    | Good for `day == 1`                   |
| Can become lengthy with many conditions | Often cleaner with many fixed choices |


17]Ternary Operator
 - The ternary operator is a compact, single-line alternative to if-else that evaluates a condition and returns one of two values 
 — useful for simple conditional assignments where you want cleaner, more concise code.

20]Declaring without initializing
- Local variables: allowed to declare, but compiler throws an error if you try to use it before initializing (variable might not have been initialized)
- Instance/static variables: automatically get default values (0, false, null), so no error even if unused

21]Infinite loop
Eg:
for (;;) { }
while (true) { }
Common in server applications or listener threads that must run continuously until explicitly stopped.

22]Return type vs void method
A method with a return type sends a value back to the caller (return value;); a void method performs an action but returns nothing.

23]Method overloading and its rules
Defining multiple methods with the same name but different parameter lists within the same class.
Rules:
Must differ in number, type, or order of parameters
Return type alone cannot differentiate overloaded methods
Access modifiers can differ freely
